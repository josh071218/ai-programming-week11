# AI 협업 프로그래밍 11주차 실습

## 1. 프로젝트 목적
성적 CSV 파일을 읽는 load_scores(path) 함수를 대상으로 직접 설계한 테스트와 AI가 생성한 테스트를 비교한다.

## 2. 입력과 출력
입력: name,score 헤더가 있는 CSV 파일 경로
출력: (kept, skipped) 튜플
- kept: 유효한 (이름, 점수) 목록
- skipped: 제외된 행의 번호, 원본, 이유를 담은 목록

## 3. 실행 방법
Python과 pytest, pytest-cov를 설치한 후 아래 명령어를 실행한다.

```powershell
py -m pytest test_load_scores.py -v
py -m pytest test_ai_A.py -v
py -m pytest test_ai_B.py -v
```

## 4. 테스트 결과
| 구분 | 통과 | 실패 | 커버리지 |
|---|---:|---:|---:|
| 직접 작성 | 9 | 0 | 80% |
| AI A (코드 제공) | 16 | 0 | 80% |
| AI B (명세 제공) | 2 | 13 | 80% |

## 5. 발견한 문제
AI B는 10주차 명세에 따라 목록 하나를 반환값으로 예상했지만, 실제 11주차 프로그램은 (kept, skipped) 튜플을 반환한다. 이 차이 때문에 B 테스트 13개가 실패했다. 세 테스트의 커버리지가 모두 80%라는 점에서 커버리지만으로 테스트의 정확성을 판단할 수 없었다.

## 6. AI 활용과 배운 점
AI A는 실제 구현을 참고하여 다양한 테스트를 생성했지만, 구현에 존재하는 오류까지 정답으로 받아들일 위험이 있다. 따라서 테스트를 만들 때는 코드를 보기 전에 명세에 기반한 기대 결과를 정해야 한다. 함정 실험에서는 AI가 생성한 테스트의 import 경로 오류로 실행이 중단되었으며, 확인된 기대값에서 버그 고착 사례는 발견되지 않았다.


## 데이터

### 데이터 출처
- AI 협업 프로그래밍 12주차 실습 수업에서 배포한 성적 데이터
- 분석 파일: `week12/scores_2026.csv`
- 검증 파일: `week12/mini.csv`
- CP949 인코딩 예제: `week12/scores_2026_cp949.csv`

### 데이터 크기
- 원본 데이터: 114행, 5열
- 정제 후 데이터: 100행, 5열
- 검증용 mini.csv: 10행(정제 후 7행)

### 열 설명
| 열 이름 | 설명 |
|---|---|
| 학번 | 학생 식별 번호 |
| 이름 | 학생 이름 |
| 반 | 학생이 속한 반(1반 또는 2반) |
| 과목 | 수학, 영어, 프로그래밍 |
| 점수 | 과목별 성적(0~100점 정수) |

### 데이터 정제 방법과 이유
1. 점수가 비어 있는 행 6개 삭제: 실제 점수가 없으므로 임의의 값을 넣으면 평균이 왜곡될 수 있기 때문이다.
2. 모든 열이 완전히 같은 중복 행 4개 삭제: 동일한 성적이 중복 집계되는 것을 방지하기 위해서이다.
3. 반과 과목의 앞뒤 공백 제거: 동일한 반이나 과목이 서로 다른 그룹으로 분류되는 것을 방지하기 위해서이다.
4. 점수가 0~100 범위를 벗어난 행 4개 삭제: 정상적인 점수 범위만 분석하기 위해서이다.
